# Zephyr user guide

How Zephyr's windows, pages, files, previews, export and agent access behave.

## Theme files

Every theme has an editable JSON file. **Settings → Theme → Edit Theme File** opens the current file; **Advanced → Theme folder → Show in Finder** reveals it. By default the files live in `~/Library/Application Support/Zephyr/Themes/`: the four built-in themes are in `Built-in/`, and custom themes are beside that folder. Saving a valid edit updates open windows. Invalid edits leave the last valid appearance in use and show an error; the file is left intact so it can be corrected.

At first launch, earlier built-in adjustments are copied into complete theme files. Later launches create missing files. When an update changes a value a built-in theme ships with, its file takes the new value only where it still holds the old one; values you changed stay (`Built-in/.revision` records which changes a folder has had). The selected theme and legacy settings remain in `appearance.json` outside the app bundle. **Restore Defaults** is an explicit replacement of the selected built-in theme and supports Undo.

## The sidebar and the app's pages

New windows open with the full sidebar; hiding or showing it with the sidebar button carries over to the next window. It lists **Pages** and **Open**, then the folder: **Home** followed directly by its files and subfolders. In icons-only mode, the folder icon (**Files**) opens the folder in a panel beside the strip, as tall as it, with Files marked while it shows; the strip and document keep their size and position. Choosing a file, Escape, a click elsewhere or Files again closes it. Headings carry no buttons except the folder's search; new documents and pages, and the folder's other actions, are in the headings' secondary-click menus and the menu bar. Without a folder, up to four **Recent** documents appear in names mode. Pages lists **Activity** and the pages you make. Pages are permanent places, not open documents: one shows over the current document (which stays open beneath it) and joins back/forward history; ⌥⌘1 opens Activity, ⌥⌘N creates a page, and ⇧⌘O searches pages, recent documents and folder files together.

The interface's typeface and the sidebar's text size and row spacing belong to the theme (**Settings → Theme → Interface**, or `font.interface`, `sidebar.size` and `sidebar.spacing`). The typeface is the system font by default; another family applies at once to the sidebar, top bar, outline, panels and Settings, while menus keep the system font. The sidebar stays beside the reading area. Where the window has room, the reading area keeps a narrow strip on each side for the rails (the open documents' dots on the left, the outline's ticks on the right) whether or not they show, and the document centers between the two strips, so it sits in the same place with or without an outline. With the sidebar collapsed the text is centered in the window; beside an open sidebar it centers between the sidebar's edge and the outline's ticks, the same distance from each. Drag its right edge to change its width, with a 220 pt minimum for names. **Settings → General → Sidebar** is the only place to enable the vertical icons-only mode; narrowing the window or dragging the edge never changes modes. Returning to names restores the saved width. Icon rows immediately show names and paths under the pointer. After the configured preview delay (0.8 seconds by default), document rows show a rendered Markdown opening without switching tabs, and once one shows, the next row's follows at once; open documents include unsaved text. The card uses the current theme and does not load remote images. Moving away or scrolling dismisses it. Sections and folders expand immediately, without rolling or distorted rows. Names and paths also remain available to accessibility.

A window can hold several documents, like browser tabs without a tab bar: they are listed in the sidebar's **Open** section (from the first one, documents only), and each keeps its own back/forward history, place, undo and assistant chat. A file opened from the sidebar, the path menu, Open Quickly or a page gets its own row there, and opening it again shows that row; only a link followed in the text replaces the shown document (⌥-click a link to open it beside). Same-named files show their folder. ⌘T makes an untitled one in the window; click a row, ⌃⇥ / ⌃⇧⇥ or the documents' rail to switch. ⌘W closes the shown document and frees it (on a page, it puts the page away); a row's ×, middle-click, or **Close / Close Others / Close All** in its menu do the same for that row. When the last document closes, the window stays on Activity; ⌘W there, or ⇧⌘W anytime, closes the window. An untitled document holding text is never replaced in place: what you open from it goes beside it. An empty untitled document closes without asking to save, and closes by itself when you switch to another document or open a file beside it. Documents opened from the Finder follow the system's tab preference (a new window by default). With the sidebar hidden, they show as dots on the left edge, mirroring the outline's ticks on the right: point at them and they open into a list of names; click one to switch, or the × at the end of a row to close it. Turned off (Settings → General → Quick switcher), or in a window too narrow for it, a small number beside the sidebar button counts them instead.

Folder Home groups Markdown files by folder and links to an existing README or index. **Show as Page…** presents a chosen Markdown file as a board without creating a file in your folder. Custom pages live in `~/Library/Application Support/Zephyr/Space/Pages`: H1 is the title, H2 starts a block, and its contents become tasks, document links, `- Label: value` figures or rendered Markdown. Optional `<!-- zephyr: wide -->` and live `activity`/`recent` blocks control presentation. Presets offer blank, folder knowledge home and dashboard. Existing Today/Goals notes and their custom live blocks remain readable.

Activity counts distinct files opened each local day, successful saves and changes observed when a folder is refreshed. The first scan establishes a baseline; there is no background watcher. Counts and opaque path identifiers stay in app-owned storage (up to 365 days, 1.5 MB); busy days display `+` when the daily identifier cap is reached. Each column is a week; the record keeps the latest weeks visible as the window narrows, clipping earlier ones. Below it, **Recent Folders** shows up to four recently used folders with truncated paths; the full list remains under **File → Open Recent**.

## HTML, badges and images

Zephyr draws the HTML that README files use with its own layout, not a web view: centered or right-aligned blocks (`<p align="center">`, and `<div align="center">` around Markdown headings, text and badges), headings, links, images sized with `width` and `height` (points or percent), `<br>`, `<kbd>`, `<sub>` and `<sup>`, `<mark>`, `<details>`, and `<picture>` with a dark-mode source. Scripts, styles, frames, forms and HTML tables are never drawn; a block that holds one shows as source. Move the caret into an HTML block to edit its source; ⌘-click a link in it to open it.

Static shields.io badges (`img.shields.io/badge/…`) are drawn by Zephyr, so they show offline and in Finder previews. Other images on the web load over HTTPS, without cookies. To keep documents offline, turn off **Remote images** in **Settings → General**; a click on a waiting image then loads that document's images while it is open.

Animated GIFs, local or remote, play in place while they are on screen in the active window: at most two at once, each holding two frames at its drawn size, and one that scrolls away, is covered or belongs to another document stops and lets go of its memory. Reduce Motion, Low Power Mode and **Settings → General → Animated GIFs** keep every GIF still, and GIFs over 600 frames stay stills. Print and export draw the first frame. Zephyr does not run scripts in documents: code such as TypeScript or three.js is shown as highlighted source, and an embedded web page is not rendered inside the canvas (a link still opens the bounded hover preview).

## Writing shortcuts

`> ` shows as a quote line, bar included, as soon as it is typed. Typing `$` or `*` adds its partner with the caret between; typed again in the empty pair they nest (`$$`, `**`, `***` at most), and after text the closing mark is stepped over. This also holds at the start of a line and right beside Chinese, Japanese or Korean text, where no space is typed; a space typed inside a lone pair at the start of a line (`*‸*`) turns it into a bullet, so `* ` still starts one. With text selected, `*` or `$` wraps it, and Backspace in an empty pair removes both marks. Return after `$$` makes a formula block, and after an opening fence (```` ``` ````, optionally with a language) a code block, with the caret inside; the language list after a fence starts with **No Language**, so Return alone leaves it blank. A `!` at the start of a line or after a space offers **Image** (`![]()`) and **Image…** (choose a file) under the caret: ↓ or the pointer picks one, and Return without a choice simply starts a new line. Typing the `>` of an opening HTML tag such as `<sup>` adds its closing tag after the caret. **Underline** (⌘U, `<u>`), **Strikethrough** (⇧⌘X, `~~`) and **Highlight** (⇧⌘H, `<mark>`) are in the Format menu, the text's secondary-click menu and the slash menu.

## Find, replace and search

**Find** (⌘F) opens Zephyr's own bar at the top right of the reading area, with the selection in it: matches are highlighted on the page, the counter shows where you are (3 / 12), Return and ⇧Return (or ⌘G and ⇧⌘G) go to the next and previous match, and Esc closes it. The switches beside the field are **Aa** (match case), **ab** (whole word) and **.\*** (regular expression); without them, case, accents and full-width forms are ignored. **Find and Replace** (⌥⌘F, or the arrow at the bar's left) adds a Replace row: Return there, or **Replace**, replaces the selected match and moves on; **All** replaces every match as one undo step. In regular-expression mode the replacement reads `$1` for a group and `\n`, `\t` for a line break and a tab. ⌘E puts the selection into the field, and the last search is shared with other apps through the system find pasteboard.

**Search in Folder** (⇧⌘F) lists lines containing the text, as before, and below them, under **Related**, the passages of the folder's files that best answer the words you typed: a question, a topic, other wording, Chinese or English. Ranking looks at words (Chinese by pairs of characters, so no segmentation is needed), counts a heading and the file's path more than the text, and adds a few near neighbours of each word from the system's own language data. Nothing is indexed or kept: the files are read when you search, a few at a time, and nothing runs afterwards. It finds what shares words with your query; it does not translate between languages. `zephyr search TEXT [folder] --related`, `zephyr find TEXT --related` and the `search` tool's `related` argument give agents the same ranking.

## File integration and export

**Settings → General → Documents** offers the default Markdown editor and Finder Quick Look preview actions. Default opening and Space-bar preview are separate macOS choices; Zephyr includes a native preview extension using the same Core Text canvas.

Quick Look renders the document supplied by Finder with the selected theme's typography, supported CSS, palette and light/dark mode. Images outside the extension's accessible scope show an unavailable-resource hint.

**File → Export As…** is one command. Its save panel chooses PDF, HTML, PNG, JPEG or plain text, the selected or a fixed theme, and light, dark or follow-system appearance (**Follow System** uses the Mac's appearance at the moment of export), and the format's options (paper size and margins; raster width and scale). It starts from **Settings → Export**, and an export keeps its choices there, so the CLI uses the same defaults and accepts explicit overrides. PDF and page images use the rendered canvas even when the editor shows source; HTML is a safe semantic document, with formula/diagram source retained. Local images are resolved from the original Markdown directory; remote images remain unloaded. Multi-page images use numbered files. Exporting does not change the source or its undo history.

Hovering over a link shows a bounded, scrollable native preview of actual local/remote Markdown, PDF, image, code/text or readable web content. Line anchors such as `sample.swift#L3-L6` show that numbered excerpt; GitHub blob links and remote plain text support the same line ranges. Oversized local text without line anchors shows an Open hint; anchored files use bounded streaming. Web previews extract readable HTML or structured article text and show a labelled metadata summary when only a client-rendered shell is available. Offline, lost connections and timeouts have explicit messages; local previews remain available. The link context menu also offers Preview Link. General settings controls the hover delay or turns it off. The Ask AI footer prepares a draft without sending it. Hover previews use no WebView or scripts. An explicit **Page snapshot** action briefly renders the URL in nonpersistent WebKit, captures a passive image and releases the web view; **Text preview** immediately cancels an in-flight render and restores the original content. Only one render runs across windows, with an eight-second deadline, a fixed 1024×640 desktop viewport and a maximum 1280×800-pixel snapshot. Blank client-rendered shells are checked only within that deadline and show a compact failure card if content does not appear. Media, fonts, child frames, dialogs and media permissions are blocked; the macOS 27 geolocation delegate explicitly denies location permission. Complex pages can temporarily increase WebKit process memory; this is not a hard overall memory cap. No site-specific API or persistent page cache is used.

Built-in themes use a 896–960 pt reading column on wide screens. Tables use their content's natural width by default, up to that column; Column Width and Window Width remain explicit layout choices. The strips that add a row (bottom edge) or a column (right edge) stay invisible and appear, with their plus, only while the pointer is on one after leaving the table across that edge, never when it approaches from outside; clicking a cell puts the caret where you clicked. **Settings → Theme → Charts and images** chooses centered (default) or left for pictures, including Markdown images with titles; explicit HTML alignment takes precedence. This setting changes presentation without editing the file. Local images can be resized with an undoable Markdown edit; explicit HTML alignment remains supported. Mermaid flowcharts are laid out by Zephyr itself: with curved lines (the default) every link is one smooth curve, and a link that returns to an earlier step sweeps around the nearer side without crossing a box; every link label sits on its own line, never over another one. A single image/Mermaid click opens its preview after the system double-click interval; a double-click enters its Markdown source instead. Dragging cancels the pending preview. Hover reveals expand and action buttons; the action menu contains only source copying and bounded PNG saving. The expand button or ⌘Return shows the centered component over a stronger blurred backdrop confined to the reading area. The upper-right × always closes it; clicking outside or Escape also returns to the document. Swipe down to zoom out, swipe up to zoom in, drag to pan, or double-click to edit Markdown. Drag a table's inner column divider to redistribute the adjacent columns and reflow their text. Column widths stay with the current table while editing cells or rows; reopening the document restores its natural layout, without adding layout data to Markdown. Double-clicking the rendered component also edits Markdown directly. Undo and redo preserve rendered components. Fenced code is colored by the language after its opening fence (```` ```json ````, `python`, `bash`, `swift`, `js`, `yaml`, `html`, `css`, `sql`, `diff` and about twenty more): keywords, strings, numbers, comments, function names and keys, in colors worked out from the theme's accent so each theme keeps its own look; **Settings → Theme → Code → Syntax colors** turns it off. Link previews of source files use the same colors. Source mode (⌘/) colors Markdown markers, with distinct colors for heading levels; visible-line styling preserves every character and does not parse the whole document. Lines longer than 20,000 UTF-16 units stay plain for responsiveness.

Preview cards label the source and presentation type. PDFs and images use a proportional image area. Local Word, Excel, PowerPoint, iWork, OpenDocument and RTF files request an actual system thumbnail, not a file icon: regular files up to 16 MiB, at most 1024×1024 pixels, one request across windows and a four-second deadline. Thumbnail detail depends on the installed system provider and may show only part of a spreadsheet or document. Missing providers, oversized files and unsupported packages retain an Open hint. Remote binary documents show their type, reported size and Open action without downloading the body.

JSON, XML and common source files receive native syntax colors. Clicking next to a bracket or selecting it highlights its matching `()`, `[]` or `{}`; strings and comments are excluded. The original text and line anchors remain intact. At most 16K source characters are displayed, without folding, reformatting or a language-server process. Image-only previews disable Ask AI.

## Reading controls and the assistant

The document has no scroll bar, in any "Show scroll bars" setting: it scrolls by wheel, trackpad and keys, and the outline's ink mark shows where the reading is (it follows the text and stays, beside the accent tick of the section holding the caret). Click a tick to jump. A document without headings has no position mark.

The assistant panel starts closed, and its corner button is hidden by default. **Settings → General → Assistant button** shows the entry. Existing explicit preferences are retained, and ⌘J opens the assistant with either choice.

## App updates

**Zephyr → Check for Updates…** and **Settings → General → Updates** check the signed GitHub release feed. Automatic checking is on by default and runs daily. **Install automatically** is a separate opt-in: downloaded updates can install when you normally quit. Turning off automatic checking also turns off automatic downloading; manual checks remain available. An explicit installation still lets macOS review unsaved documents and cancel quitting.

Updates replace the app bundle. Theme JSON files, `appearance.json`, preferences, activity, pages and document history stay in their existing locations outside it. Downloading a new version from GitHub and replacing the app manually preserves the same configuration. Version 0.1.2 introduces the updater; people using 0.1.1 or earlier must install an updater-enabled version manually once.

## Agents and the `zephyr` CLI

Agents never write files. Shared-document commands require an existing, unexpired explicit session; the filename menu no longer grants agent access. The CLI bundled in the app (`Zephyr.app/Contents/Helpers/zephyr`) can read that shared document as currently edited, search it or its folder, and propose edits. Every proposal opens a review sheet in Zephyr, and applied changes can be withdrawn from the AI panel. Only the bundled CLI may connect, checked by code signature.

```bash
zephyr context                                  # path, revision, selection, outline
zephyr read --lines 1:40                        # numbered lines of the shared document
zephyr find "release date" --folder             # search the folder scope
zephyr propose --find "Monday" --replace "Friday" --summary "Move the date" --wait
```

Without a shared document, `zephyr outline <file> [--depth N]` and `zephyr stats <file>` use the app's core implementations. `zephyr activity [--days N]` reads daily activity, `zephyr home [folder]` lists a folder homepage, and `pages`/`page` read custom Markdown boards. Historical `today`/`goals` commands remain available. `config`/`theme` change appearance settings.

`zephyr export input.md --format pdf --output /chosen/path/report.pdf` explicitly writes a derived output from the saved file using the shared exporter and active theme. **Settings → Export** holds the defaults it shares with File → Export As: format, theme, appearance, text size (11 pt by default, sized for A4 or Letter pages) and line height (or the theme's own), margins around PDF pages and images, paper size for PDF, page width and scale for images; `--text-size 12`, `--line-height 1.5` or `--appearance dark` (`system`, `light`, `dark`) override them for one run. Existing targets require `--overwrite`; the Markdown input is always protected. The GUI exports its current edited text. MCP retains its read/search/propose permission boundary and has no export tool.

`zephyr mcp` serves the same over MCP on stdio: `get_context`, `search`, `read` and `propose_patch` for documents, `get_appearance` and `set_appearance` for themes. They are defined once (`sources/core/agent/DocumentTools.swift`); the built-in assistant uses `read`, `search` and `propose_patch` from the same definition. **Settings → Agents** shows the exact CLI path and an MCP configuration to copy. For example:

```json
{ "mcpServers": { "zephyr": { "command": "/Applications/Zephyr.app/Contents/Helpers/zephyr", "args": ["mcp"] } } }
```

API keys for the assistant are encrypted by Zephyr in `~/Library/Application Support/Zephyr/` (readable by you only, bound to this Mac); Zephyr does not use the keychain.
